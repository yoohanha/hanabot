## 🚧 개발 중 막혔던 부분 3개

### **1️⃣ Template Literal 문법 오류 (996줄)**

**문제:**
```
모든 동적 페이지(page.html)에서 "로드 중..."에 무한 로딩
브라우저 콘솔: "Unexpected token '<'" SyntaxError
```

**원인:**
```javascript
// 996줄 (잘못된 코드)
const html = `
  ...
  </style>;  // ← 세미콜론이 Template Literal을 조기 종료!
  <div>...</div>
` // ← 이것이 문자열이 아님
```

**해결:**
```javascript
// 수정된 코드
const html = `
  ...
  </style>  // 세미콜론 제거
  <div>...</div>
`
```

**배운 점:** Template Literal 안에서 세미콜론은 단순 문자임

**커밋:** `5934d84 [3-3] 학원소개 페이지 템플릿 문자열 오류 수정`

---

### **2️⃣ 함수 스코프 문제 (Markdown 렌더링)**

**문제:**
```
과정 테이블과 학원소개 페이지의 마크다운 변환 실패
브라우저 콘솔: "markdownToHtml is not defined"
```

**원인:**
```javascript
// script.js에서 정의된 함수
function markdownToHtml(text) { ... }

// page.html의 inline script에서 호출하면?
// → HTML의 스코프에서 script.js의 함수를 볼 수 없음
```

**해결:**
```javascript
// page.html 내부에 로컬 함수 정의
const markdownToHtmlLocal = (text) => {
  return text
    .replace(/\*\*(.+?)\*\*/g, '<strong>$1</strong>')
    .replace(/^- /gm, '• ')
    .replace(/\n\n/g, '</p><p>');
}
```

**배운 점:** Inline script와 외부 JS의 스코프 차이 이해 필요

**커밋들:**
- `1a2f52e [3-3] 과정 테이블 오류 수정`
- `29145b2 [3-3] 학원소개 markdownToHtml 함수 오류 수정`

### **3️⃣ 채팅 UI가 일부 페이지에서 없음**

**문제:**
```
index.html에는 채팅이 있지만,
page.html, course-*.html에서 "🤖 하나봇" 버튼이 없음
```

**원인:**
```html
<!-- index.html -->
<div id="chatModal">...</div>
<button id="floatHanabot">🤖</button>
<!-- script.js에서 이들을 찾아 초기화 -->

<!-- page.html -->
<!-- 이 요소들이 없으면 script 실행 중 오류 발생! -->
```

**해결:**
```javascript
// script.js에 initializeChatUI() 함수 추가
function initializeChatUI() {
  if (document.getElementById('chatModal')) return;
  
  // 없으면 자동으로 HTML 생성
  document.body.insertAdjacentHTML('beforeend', `
    <div id="chatModal">...</div>
    <div class="floating-buttons">...</div>
  `);
}

// DOMContentLoaded에서 호출
initializeChatUI();
initializeChat();
```

**배운 점:** UI는 "있으면 초기화, 없으면 생성"하는 방어 로직 필요

**커밋:** `1731637 [3-3] 하나봇 채팅 모든 페이지 적용 (UI 자동 생성 · 버튼 통일)`

## 💡 AI에게 일을 잘 시키는 방법 5가지

내 프롬프트 기록에서 뽑은 성공 패턴:

### **1️⃣ 명확한 최종 목표 먼저 제시**

**좋은 예:**
```
"홈페이지 시간표를 실제 커리큘럼으로 바꾸자. 
시간표 원본은 data/RAG_PLAN.md 라서 그 파일부터 고칠 거야."
```

**이유:** AI가 전체 맥락을 이해하면 중간중간 판단이 쉬워짐

---

### **2️⃣ 오류 메시지 → 원인 분석 → 해결 힌트 함께 제공**

**좋은 예:**
```
"page.html이 모든 페이지에서 '로드 중...'에서 멈춰. 
스크립트 문법 오류 때문이야."
```

**이유:** 단순 오류 리포트만 주면 AI는 무의미한 디버깅을 반복함

---

### **3️⃣ 한 번에 하나의 작은 작업만 요청**

**좋은 예:**
```
"markdownToHtml 함수 오류를 고쳐줘."
(일부 완료)

"이제 학원소개 페이지 내용을 작성해줘."
```

**나쁜 예:**
```
"홈페이지 전체를 완성해줘. 과정, 학원소개, 채팅, 신청, 디자인 모두"
```

**이유:** 큰 작업은 작은 단계들로 쪼갤 때 품질이 높음

---

### **4️⃣ 직접 사례를 보여주기**

**좋은 예:**
```
"이런식으로 테이블로 커리큘럼이 나오길 바래"
[테이블 사진 첨부]
```

**이유:** 말로 100번 설명하는 것보다 사진 1장이 더 명확함

---

### **5️⃣ 선택지를 제시하되, 추천은 하지 않기**

**좋은 예:**
```
"다음 중 선택해주세요:
A) 고쳐달라: HTML에 maxlength 속성 추가
B) 넘어간다: 현재 상태 유지 (백엔드 검증으로 충분)"
```

**이유:** AI가 사용자 의도를 존중하고 협력적 느낌을 줌
